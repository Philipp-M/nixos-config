# Voice-control preferences

- Preserve these behaviors when editing this module or its configuration in `../../configuration.nix`.
- English recordings of 1–3 words: lowercase all text and remove trailing dots. German: remove trailing dots only; preserve capitalization. Do not apply short-recording rules to fragments of longer recordings.
- Keep Whisper vocabulary empty; use deterministic contextual aliases, not LLM rewriting.
- Normalize `draw x` spelling/casing/separator variants (including `drawX`, `DrawX`, `draw-x`) to `droix` in all contexts, including prose. Only terminal command heads may map `strikes`/`strokes` to `droix`.
- Terminal zoxide: `z-droix`, `zdrawx`, `c droix`, and equivalent joined/separated known-name variants mean `z droix`; accept `c` as a spoken `z` before a directory query. Also split arbitrary joined leading `z` in terminal context (`zm/` → `z m/`); do not generalize this to joined `c` identifiers.
- In terminal context, a leading standalone/spoken `Z` ALWAYS means lowercase `z`, never prose. Lowercase the entire following zoxide path/query, including German, streamed fragments and multi-word queries. Interpret following dash/minus as path-name hyphens, not option separators. Keep `z dot` literal. Never revert this to case-preserving path normalization.
- At the start of a terminal recording, a leading whole word `the` (any casing) is a German-accent recognition alias for `z`, alone or before a query (`the MyProject` → `z myproject`, `the dot` → `z dot`). Preserve mentions inside sentences, later streamed fragments, longer words such as `theory`, and other application modes.
- Terminal `Satura`/`satura`/`SATURA` and phonetic `zatura`/`sathura` variants mean `zathura`. Normalize these first; canonical `zathura` (also with arguments) is the sole application exception to leading-z splitting. Other contexts must retain these names.
- Terminal `zdot`, `zDot`, `ZDOT`, `z-dot`, and `z_dot` MUST normalize to literal `z dot` before spoken-dot replacement. Missing whitespace is not a reason to leave this known directory command unchanged.
- Terminal dictation primarily means commands, paths, flags, and Rust/JS/TS tooling. Preserve the alias regression corpus, including `list`/`LS` → `ll`, `find`/`fine` → `fd`, and phonetic `rg`, `nixpkgs`, Cargo, Git, SSH, and htop variants.
- Terminal command-head spelled SSH forms (`s.s.h.`, `s. s. h.`, `s s h`, `s-s-h`, any casing) normalize to `ssh`, including hosts/options. Preserve filenames, quoted arguments, sentence mentions, later streamed fragments, and other application modes.
- Terminal `skid`/`skit` (any casing) mean `git`, alone or before known Git subcommands; use the same recording-start restriction, punctuation cleanup, and argument preservation as the other Git aliases.
- Terminal Git prefixes include `kid`/`kids`/`kidz` (`kid push` → `git push`) and `skip` (`skip status` → `git status`); `def`/`tiff`/`dev` mean `diff` and `logger`/`longer`/`luck` mean `log` after a Git prefix (`good luck` → `git log`). Command corrections apply only at the beginning of a recording, never inside sentences or later streamed fragments after a pause. Keep global spoken punctuation and `draw x` normalization active throughout.
- Terminal command-head `felix` and `hey lex`/`hey, lex`/`hey-lex` are recognition errors for Helix: normalize to `hx`, including when followed by file arguments. Do not rewrite the name in other contexts.
- Complete terminal utterance `get the` means `git diff`; preserve `get the clone ...` as a Git clone alias.
- Terminal `get and` means `git add`, including file arguments and `get and dot` → `git add .`.
- In terminal context, always normalize a leading whole word `get` (any casing) to `git`, including unknown/custom subcommands. `get pushed`, `get the push`, and `get the pushed` mean `git push`, also with arguments. Preserve existing `get the`/`get and`/`get the clone` corrections; do not rewrite `get` in the middle of text or outside terminal mode.
- In all contexts, spoken slash joins path segments; dash/minus join kebab-case, but after a recognized command form spaced options (`rg -e --something`). Absorb adjacent recognition commas. Preserve explicitly quoted literals.
- Spoken `colon` means `:` in all contexts (also quotes); remove preceding whitespace/recognition commas, retain following spacing (`label colon value` → `label: value`).
- Spoken `underscore` (also `under score`/`under-score`, any casing) means `_` everywhere, including quotes and later streamed fragments. Join adjacent words and absorb recognition commas (`snake underscore case` → `snake_case`); preserve terminal command/argument spacing (`rg underscore` → `rg _`). Process dot and underscore together so combinations such as `file underscore dot rs` → `file_.rs` work.
- Spoken `hashtag` (also `hash tag`/`hash-tag`, any casing) means `#` in every context, including quotes; consume following spaces/recognition commas so it attaches to the next word (`hashtag app` → `#app`). Preserve preceding spacing.
- Terminal Nix commands must normalize joined command/flake forms: `nixrun.hashtag app` → `nix run .#app`, also for build/develop/shell/eval. Keep the space before the flake reference and none after `#`.
- Normalize nested Nix flake command words with argument tails, including update/check/show/lock. For `nix flake update`, canonicalize leading bare known input names from the declarations in `../../flake.nix` (`nix Flake Update LLM-Agents` → `nix flake update llm-agents`). Preserve unknown names, quoted text, paths and flag values; keep recording-start and application-mode restrictions.
- Across terminal commands, treat recognition commas/periods at known command/subcommand boundaries as spaces (`git,diff`, `cargo. test`, `nix.flake.update`). Preserve dots/commas inside paths, URLs, quoted arguments, standalone `.`/`..`, and `.#`/`.hashtag` flake references. Keep this shared across commands, not Nix-only.
- Terminal Git input is command syntax: separate attached flags (`git diff--compact summary` → `git diff --compact-summary`) and join known multiword long-option names using `runtime/src/git-long-options.txt`. Preserve quoted messages, option values and paths after standalone `--`; do not indiscriminately hyphenate arguments.
- Remove recognition-added final periods from terminal Git commands (`git c --amend.` → `git c --amend`), including streamed fragments. Do this before spoken-dot conversion; preserve standalone `.`/`..`, quoted punctuation and paths after `--`.
- Spoken `dot` MUST become `.` everywhere, including quoted text. The ONLY exception is the complete `z dot` directory command. Apply after short-utterance trailing-dot cleanup; preserve command/argument spacing (`rg dot` → `rg .`) and join filenames (`file dot rs` → `file.rs`). Never remove this behavior when adjusting prose rules.
- Shell aliases must stay out of higher-priority Codex/Helix modes. Never add Enter to shell corrections. Collapse repeated command aliases, not arbitrary prose or arguments.
- Explicit Helix voice-command mode: go to → definition (`gd`), back/beck → `Ctrl+o`, into → `Ctrl+i`, up/down → half-page `Ctrl+u`/`Ctrl+d`. Process matching does not detect editor mode; do not assume insert/normal state from the last injected key.
- Run `test-transforms.sh` and normal Git-backed flake evaluation. New imported files must be visible to Git (`git add -N`); direct file evaluation alone misses this failure.
